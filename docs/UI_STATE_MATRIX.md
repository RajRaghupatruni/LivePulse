# LivePulse UI State Matrix

This matrix describes the final reference-led local UI against real `PERSONAL_LOCAL` provider contracts. The landscape and portrait PNGs in `docs/ui-reference/` are the visual source of truth; these state treatments preserve those compositions. State is evidence-backed: authoritative REST snapshots, canonical events delivered over the recoverable WebSocket, normalized health, or the deterministic local Focus Timer. PUBLIC_DEMO remains backend-only isolation and has no UI state or presentation. A future desktop shell supplies the platform adapter without changing these state semantics.

`LIVE` describes the active WebSocket transport only. Provider freshness, backend readiness, infrastructure health, football lifecycle, and Focus Timer state are separate and can be visible together. All domain transitions preserve the locked landscape or portrait composition; attention may change local emphasis inside reserved geometry.

## Precedence and composition

- Server priority, evidence time, and stable domain/subject tie-breaks are resolved by `dominant_focus`; React consumes that result and never re-scores sources.
- A current live match is a persistent operational context. Goal/red-card transients can interrupt its emphasis; Gmail and CI context do not replace its score/phase.
- Focus Timer quiets peripheral presentation but is not an alert filter. Critical match events and System Pulse remain capable of gaining emphasis.
- Replayed/resynchronized items enter durable chronology without live arrival motion. Deduplicate by canonical `event_id`; preserve occurrence time and cursor ordering.
- Provider health and WebSocket transport are independent. Show both when relevant. A healthy local runtime can have an unconfigured optional source.

## Contract mapping

- `/api/v1/live-state` provides football `match`, football `focus`, and the additive server-selected `dominant_focus` signal. Football Match Mode remains separate from cross-domain attention.
- `dominant_focus` is selected using the deterministic policy in ADR 0012: football lifecycle/events; important Gmail at 85; CI failure at 80; configured degraded provider at 65. Gmail and CI transients expire after 12 seconds; degraded provider attention persists until recovery.
- `/api/v1/timeline` and durable WebSocket replay expose occurrence `timestamp`, canonical `observed_at`, source, subject, event, safe projected payload and cursor. Cursor is a recovery watermark, not a display count.
- Football fixtures, Spotify playback/commands and weather use the existing PERSONAL_LOCAL provider endpoints. System Pulse uses the independent system/provider health snapshots.
- No PUBLIC_DEMO visual mode, fixtures, label, or state transition is part of the final UI. Backend isolation tests and security protections remain in place.
