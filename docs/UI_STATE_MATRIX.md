# LivePulse UI State Matrix

This matrix defines the visual response to the requested states. Every state must be driven by an authoritative backend snapshot/event or the local deterministic Focus Timer. System-health/provider state and WebSocket transport state are independent channels. `LIVE` alone means the realtime socket is connected; it does not claim every provider is fresh.

## Cross-state precedence and composition

- System health, provider freshness, WebSocket recovery, Match Mode, and Focus Timer are separate dimensions. They may appear together; one must not overwrite another’s truth.
- A verified goal or red card may briefly interrupt a lower-priority visual transition. Important Gmail and CI events use reserved context/Timeline emphasis and do not displace an active match stage.
- Focus Timer is multiplicative quieting, not an alert filter. Critical match events and System Pulse degradation still surface.
- Replayed or resynchronized history is inserted without live entrance animation. Identity deduplication remains keyed by canonical `event_id`; ordering remains occurrence timestamp then durable cursor.
- If any provider state is stale while the system is healthy, show both facts. Optional unconfigured providers remain explicitly disconnected/unconfigured without making overall infrastructure appear degraded.

## Contract dependencies

The matrix’s football lifecycle and current goal/red-card expiry match the existing `FocusState` and focus ADR. Upcoming fixtures, Spotify playback and controls, and current weather endpoints already exist. The UI does not currently consume them. `SystemHealth` in `web/src/types/livepulse.ts` lacks `runtime_mode` and complete provider status fields; the SystemHealthPanel currently renders infrastructure components only. Gmail and GitHub are represented by canonical Timeline activity and provider health, not a user-facing inbox or current CI incident list. Cross-domain Focus behavior for Gmail/CI/provider degradation, fixture selection among multiple matches, and per-event `observed_at` freshness need explicit backend contracts before their matrix entries can be treated as live implementation behavior.
